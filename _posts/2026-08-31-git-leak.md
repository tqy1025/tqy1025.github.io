## 原理

Git 泄漏是指 `.git` 目录被意外暴露在生产环境中，攻击者可以通过访问 Git 元数据文件（如 `.git/HEAD`、`.git/config`、`.git/objects/*` 等）重建完整的源代码仓库。

`.git` 目录保存了 Git 仓库的版本管理信息，包括：

- 当前分支信息
- 提交记录
- 文件对象
- 历史版本
- 远程仓库配置
- 已经删除但仍存在于历史提交中的文件

常见结构如下：

```text
.git/
├── HEAD
├── config
├── index
├── refs/
│   ├── heads/
│   └── remotes/
├── logs/
└── objects/
    ├── info/
    ├── pack/
    └── xx/
```

其中：

- `.git/HEAD` 指向当前分支。
- `.git/index` 保存暂存区中的文件路径信息。
- `.git/refs` 保存分支和标签引用。
- `.git/logs` 可能泄漏提交记录和提交者信息。
- `.git/objects` 保存提交、目录树和文件内容。
- `.git/config` 可能泄漏远程仓库地址及内部配置信息。

## 检测方法

1. 访问 `/.git/`：返回 `403 Forbidden`，说明目录可能存在，但禁止直接浏览。
2. 访问 `/.git/HEAD`：返回 `ref: refs/heads/master` 或 `ref: refs/heads/main`，说明 Git 元数据可以读取。
3. 访问 `/.git/config`：返回 `[core]`、`[remote "origin"]` 等配置，基本可以确认存在 Git 泄漏。

```bash
curl -i https://example.com/.git/
curl -i https://example.com/.git/HEAD
curl -i https://example.com/.git/config
```

## 手工恢复原理

首先访问：

```text
/.git/HEAD
```

若返回：

```text
ref: refs/heads/master
```

继续访问：

```text
/.git/refs/heads/master
```

获得 Commit Hash。如果该文件不存在，则检查：

```text
/.git/packed-refs
```

拿到 Hash 后，将前两位作为目录、剩余部分作为文件名：

```text
Hash：e4a4d1f2c6c81f87e68c6f64fd7bc534e2c23456

对象路径：
/.git/objects/e4/a4d1f2c6c81f87e68c6f64fd7bc534e2c23456
```

如果松散对象不存在，访问：

```text
/.git/objects/info/packs
```

该文件会列出 Packfile，例如：

```text
P pack-a1b2c3d4.pack
```

然后下载：

```text
/.git/objects/pack/pack-a1b2c3d4.pack
/.git/objects/pack/pack-a1b2c3d4.idx
```

恢复过程可以概括为：

```text
HEAD
  ↓
refs/heads/master 或 packed-refs
  ↓
Commit Hash
  ↓
objects/xx/xxxx 或 objects/pack
  ↓
Commit → Tree → Blob
  ↓
文件内容
```

## 利用工具

### git-dumper

`git-dumper` 可以从允许访问部分 `.git` 文件的网站中恢复 Git 仓库。

项目地址：[arthaud/git-dumper](https://github.com/arthaud/git-dumper)

基本用法：

```bash
git-dumper https://example.com/.git/ recovered-repository
```


### GitTools

GitTools 包含用于检测、下载和提取 Git 仓库的脚本。

项目地址：[internetwache/GitTools](https://github.com/internetwache/GitTools)


使用 Dumper 下载泄漏的仓库：

```bash
bash Dumper/gitdumper.sh https://example.com/.git/ recovered-repository
```

使用 Extractor 提取各个提交中的文件：

```bash
bash Extractor/extractor.sh recovered-repository recovered-files
```


## 防御措施

1. **生产环境禁止部署 `.git` 目录**
   - 使用 `.gitignore` 排除 `.env`、密钥、日志和备份文件，避免敏感信息进入版本历史。
   - 在部署脚本中明确排除 `.git`、`.svn`、`.hg` 等版本管理目录。
   - 生产环境仅部署构建产物，不直接复制整个项目目录。

2. **限制 Web 访问**

   Nginx：

   ```nginx
   location ~* /\.(git|svn|hg)(/|$) {
       return 404;
   }
   ```

   Apache：

   ```apache
   <DirectoryMatch "/\.(git|svn|hg)">
       Require all denied
   </DirectoryMatch>
   ```

3. **定期安全检查**
   - 检测生产环境是否可以访问 `/.git/HEAD`、`/.git/config` 等文件。
   - 定期检查 Web 服务器和部署流程中的排除规则。
   - 发现泄漏后及时关闭访问，并轮换历史提交中出现过的密码、Token 和密钥。
